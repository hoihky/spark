Spark Game Engine

A desktop-focused C++23 game engine combining GLFW, a Vulkan forward renderer, entity–component simulation, custom 2D/3D physics, AI modules, audio mixing, a retained-mode GUI toolkit, and optional Dear ImGui for editor and debug tooling.

GitHub repository ↗ Quick start Programming guide Architecture docs

Overview

Spark is an experimental, education-oriented engine prototype built to explore modern C++ game architecture: explicit frame contracts, dependency inversion over concrete Vulkan types, and composition via components rather than deep inheritance hierarchies. The default binary SparkDemo ships an interactive launcher with 20 built-in modes — from 3D fly scenes and a scene editor prototype to 2D platformers, tilemap showcases, and classic arcade demos.

Explicit frame contract

Simulation runs in OnUpdate; rendering is an immutable SceneRenderParams snapshot handed to the GPU in OnRender.

Dependency inversion

Games depend on IGame and IEngineContext, not on VulkanRenderer internals.

Composition

Behavior lives in GameComponent types attached to lightweight GameObject entities.

Engine architecture

Spark separates application logic, simulation, and rendering through small interfaces and a per-frame data hand-off. This section summarizes the Architecture & Developer Guide.

Frame sequence

Each frame the engine polls input, ticks your game, pumps audio, records GPU work, and presents the swapchain:

sequenceDiagram
    participant E as Engine
    participant G as IGame
    participant S as SoundEngine
    participant V as VulkanRenderer
    E->>E: PollEvents + BeginInputFrame
    E->>G: OnUpdate(timing, context)
    E->>S: PumpFrame(delta)
    E->>G: OnRender(frame, context)
    E->>V: PresentFrame

Core types

TypeRole
EngineOwns window, VulkanRenderer, input, sound; drives the main loop.
IGameYour application contract: OnAttach, OnUpdate, OnRender, OnDetach.
GameOptional base class owning a Scene and forwarding component updates.
GameWorldEntity storage, hierarchy, asset caches, async loader pump.
SceneQuery façade: drawables, lights, sprites, tilemaps, UI canvases — no entity ownership.
SceneRenderParamsImmutable GPU snapshot: draws, lights, sprites, screen UI, textures.
IEngineContextStable gameplay API: input, framebuffer size, scene params, optional ImGui layer.

Rendering data path

flowchart LR
    ECS[GameWorld ECS] --> Fill[FillStandardLitSceneFromWorld]
    Fill --> SRP[SceneRenderParams]
    GUI[PaintUiCanvases] --> SRP
    SRP --> VK[VulkanRenderer]
    IMGUI[Dear ImGui overlay] --> VK
    VK --> Present[Swapchain Present]

For typical 3D scenes, SubmitStandardLitSceneFromWorld walks the ECS, registers textures, fills draw items (including skinned meshes and sky), sorts transparent draws, and submits sprites and tilemaps. Demos that need custom cameras or gizmos can build SceneRenderParams manually — see ThreeDDemo and SceneEditor3DDemo.

ECS model

A GameObject is a named entity with a parent/child hierarchy and a bag of components. GameWorld::UpdateGameObjects ticks every attached GameComponent in priority order (billboards, animation drivers, animators, camera rigs, then default gameplay). Components communicate on the same entity via EmitSignal / OnSignal. The engine ships 70+ built-in component types — see the component reference.

Feature catalog

Subsystem overview from the architecture guide and programming guide capabilities chapter.

3D rendering

Forward PBR

GGX specular, metallic-roughness workflow, normal and ORM texture maps, emissive HDR glow.

Toon / cel shading

Stepped diffuse bands and rim lighting via SceneShadingModel::ToonCel.

Lighting & shadows

Directional CSM, clustered point and spot lights with optional punctual shadows, SSAO, HDR tonemap.

Characters

Skinned glTF meshes, skeletal animation, attachment sockets, 3D character FSM locomotion.

World building

Heightfield terrain, sky box/dome/plane with HDR equirect, particles, decals, fog volumes.

glTF pipeline

Async rigid and skinned glTF loading on a worker thread; materials bound via MultiMaterialComponent.

2D rendering

Sprites

Textured quads with tint, sort modes, optional 2D lighting modes, flipbook animation.

Tilemaps

Multi-layer grids, tilesets, autotile, animated tiles, TMX import, gameplay walkability grid.

2D camera

Orthographic Camera2DComponent with rig helpers and Y-sort occlusion.

Minimal bootstrap

#include "spark/engine/Engine.hpp"
#include "spark/engine/Game.hpp"

class HelloSpark final : public Spark::Game {
public:
    void OnAttach(Spark::IEngineContext& ctx) override {
        auto* go = GetWorld().CreateGameObject();
        go->GetName() = Spark::Utf8String("Root");
        go->AddComponent<Spark::TransformComponent>();
    }
};

int main() {
    Spark::Engine engine(Spark::Engine::NewGame<HelloSpark>());
    engine.Run();
    return 0;
}

Quick start

Requirements: CMake ≥ 3.28, C++23, Vulkan SDK (glslangValidator on PATH), network on first configure.

cmake --preset debug
cmake --build cmake-build-debug -j
./cmake-build-debug/SparkDemo
TargetPurpose
SparkDemoInteractive launcher + 20 built-in demo modes
SparkEditor3D editor shell with dock UI (editor-debug preset)
SparkScriptHostC# scripting host via CoreCLR (-DSPARK_BUILD_INTEROP=ON)
External games can link Spark as a library — see game_template/ and samples/ with SPARK_ROOT pointing at this repository.
