Component script bindings — architecture

C# cannot call C++ GameComponent methods directly. The pipeline treats SparkInterop.h as the stable C ABI contract. Component headers are the source of truth for what should exist; interop exports define what C# can call today.

See also C# interop (ClangSharp + SparkInterop) for building and running SparkScriptHost.

Layers

LayerArtifactRole
1SparkInterop.h + SparkInterop*.cppC ABI + manual thunks
1bSparkInteropComponentBindings.generated.*Auto thunks from SPARK_SCRIPT_BIND
2Native.g.cs, Native.Interop.g.csP/Invoke
3Components/FromInterop/*.g.csUsable component mirrors
4GameObject.ComponentAccess.g.csGetOrAdd* accessors

Regenerate

./tools/generate-csharp-bindings.sh

Runs bindgen, ClangSharp, mirror codegen, binding-coverage.json, and the component registry. CMake also runs spark_script_bindgen.py when building SparkInterop.

Closing gaps

  1. python3 tools/scan-cpp-component-api.py → scripting/bindings/binding-coverage.json
  2. Add SPARK_SCRIPT_BIND on *Component.hpp, then regen
  3. Re-run ./tools/generate-csharp-bindings.sh

Kinds that need constructor args use spark_object_add_* in SparkInterop.h and GameObject.Add* in CppMirrors.g.cs (not GetOrAdd*).
